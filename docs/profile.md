# Профиль, согласия и часовой пояс

Этап FIN-219 добавляет GetProfile, UpdateProfile, GrantAssistantConsent,
RevokeAssistantConsent и GetAssistantConsentStatus. Создание заявки,
подтверждение и Watch — [verification.md](verification.md). Удаление описано
в [deletion.md](deletion.md). API-тесты используют явно тестовые документы и пользователей;
регистрация реальных пользователей требует утверждённых документов согласий.

## Доступ и чтение

Профиль доступен только bank-bff с проверенным пользовательским токеном. User ID берётся
из sub в reqctx, не из запроса. Интерцептор проверяет tombstone на primary. GetProfile
читает профиль и согласие одним SQL-снимком через обычную маршрутизацию DB.Reader:
реплика по умолчанию, primary с x-read-primary. Ответ пишущего метода читается в его
primary-транзакции. Отсутствующий пользователь — NOT_FOUND.

Внутренний GetAssistantConsentStatus вызывает только assistant, в системной модели,
с обязательным UUID user_id. Поле токена пользователя, если прислано, не заменяет user_id.
Это явная таблица grpc-api.md 3.3; общий текст и комментарий proto упоминают смешанную
модель, но зарегистрированная политика следует таблице. Вызов bank-bff отклоняется.
Статус берётся с primary под тем же tombstone guard, что и записи, без кэша. После
удаления пользователь получает TOKEN_REVOKED; несуществующий ID — NOT_FOUND.

## Настройки

Пустой PATCH и повтор тех же значений сохраняют профиль без новой записи outbox.
Тема — system/light/dark; явный THEME_UNSPECIFIED и неизвестное значение отклоняются.
Пояс — существующее имя IANA длиной до 64 байт; UTC принимается, Local и произвольный
путь файла — нет. База time/tzdata включена в бинарь, поэтому в distroless валидация
не зависит от файлов часовых поясов ОС. Правило 72 часов проверяет клиент, не user.

Записи сериализуются: primary-транзакция → tombstone Guard → FOR UPDATE строки
app_user → проверка текущего снимка → запись. Смена темы сохраняет settings_version;
реальная смена timezone увеличивает его на один и пишет событие в той же транзакции.
При ошибке публикации откатываются и профиль, и событие. Достигнутый максимум int32
не переполняется: новая смена пояса завершается внутренней ошибкой, тема всё ещё меняется.

## Согласие помощнику

Версия документа хранится в истории user_consent; у пользователя не больше одного
активного согласия assistant. Grant проверяет текущую версию в своей транзакции.
Несовпадение — CONSENT_OUTDATED; повтор текущего действующего согласия не меняет дату.
При принятии новой версии прежняя активная запись отзывается, новая добавляется.
Revoke закрывает активную запись, повтор без активного согласия ничего не меняет.
История согласий и ответов помощника не удаляется. При обратном ходе часов revoked_at
не становится раньше granted_at.

В ответе granted означает действующее согласие именно на текущий документ: после
публикации новой версии старая версия остаётся в version, но granted=false. После
отзыва version отсутствует. Текущая версия assistant должна быть опубликована в
consent_document; её отсутствие — внутренняя ошибка конфигурации данных, без
выдуманной версии или разрешения передачи данных.

## Outbox

Используется выпущенный go-outbox v0.2.0 (FIN-244), его источник миграций включён
перед миграциями user. `internal/app/outbox.go` создаёт `NewPublisher(a.DB, time.Now)`:
`Publish` получает контекст callback транзакции производителя (`db.Run`/`RunMapped`),
пишет событие и `pg_notify` через `a.DB.Tx(ctx)`, не завершая транзакцию. Без её
контекста возвращает `outbox.ErrNoTransaction`; уведомление приходит только после commit.
Производитель пишет тему user.timezone_changed, ключ user_id и protobuf
SetUserTimezoneRequest{user_id,timezone,settings_version}. Получателей производитель
не выбирает. OUTBOX_TIMEZONE_TARGETS по умолчанию bank-statement-data,assistant;
перечень — 1–64 уникальных имени, каждому требуется PEER_<NAME>_ADDR. Неверная настройка
или отсутствующий адрес останавливает сборку сервиса. Это не сетевой health-check:
недоступный настроенный сосед не мешает запуску и пользовательским изменениям.

Для worker открывается отдельный primary-пул OUTBOX_DB_MAX_CONNS (по умолчанию 8),
не меньше числа уникальных получателей обоих маршрутов + 3 (по умолчанию минимум 6). Он не использует пул пользовательских транзакций.
Диспетчер передан как `worker.Job{Name: "outbox", Run: dispatcher.Run}`; конструктор
не запускает горутины. `Dispatcher.Run` получает lifecycle-контекст сервиса вне
транзакционного callback. Контекст с транзакцией go-postgres немедленно возвращает
`postgres.ErrForeignTransaction`, до обращения к пулу и запуска горутин. Остановка
отменяет контекст и ждёт завершения задания до закрытия пула. Запасной poll
настраивается, по умолчанию 3 секунды.

Внутренний `go-postgres.Manager` доставщика привязан к одному выделенному соединению,
независимо от Manager производителя. Короткая транзакция выбора с `FOR UPDATE SKIP LOCKED`
получает session advisory lock `-id` и завершается до сетевого вызова. Lock остаётся
на соединении до сохранения результата доставки; fanout выполняется вторым коротким
`Run` на том же соединении. Успех удаляет строку, ошибка сохраняет повтор после RPC,
вне транзакции выбора. Если lock мог быть получен, соединение физически закрывается
при освобождении, в том числе при ошибке, отмене, панике или `runtime.Goexit`; оно
не возвращается в пул с lock. Поэтому при оценке нагрузки учитывайте новое
DB-соединение на доставку. Отрицательное пространство одноключевых advisory locks
зарезервировано go-outbox; другим компонентам той же БД его использовать нельзя.

Доставка — штатный клиент с метриками и ограниченными повторами UNAVAILABLE для
идемпотентного SetUserTimezone, внутри durable retry go-outbox. На каждый RPC есть
дедлайн 30 секунд и сервисный токен user. Пользовательский токен, IP и клиентская
версия не пересылаются. Получатели должны применять только большую settings_version;
для tombstone — OK без записи. Порядок доставки не гарантируется. Подтверждённый
получатель удаляется независимо от остальных; после перезапуска остаются задания
недоставленных получателей.

Register публикует начальный пояс через отдельный `NewPublisher(pool, time.Now)`
в `internal/app/sessions.go`, привязанный к auth-пулу и контексту его транзакции.
Контекст другого Manager не даёт publisher доступа к транзакции. DeleteAccount удаляет
ещё не доставленные события пояса и пишет user.deleted для PurgeUserData. Второй
маршрут OUTBOX_DELETION_TARGETS обязательно включает bank-statement-data, analytics
и assistant; PEER_ANALYTICS_ADDR требуется уже при старте. Получатели защищают
отложенные записи своим tombstone. Подробности — [deletion.md](deletion.md).

## Наблюдаемость и проверки

На /metrics публикуются библиотечные finassist_outbox_rows{target},
finassist_outbox_oldest_age_seconds{target}, finassist_outbox_delivery_errors_total{target}.
Метки ограничены настроенными получателями, пустым target до fanout и unconfigured.
Нет user_id, payload, телефона, токенов или текста ошибки соседа. Снимок backlog
обновляется независимо от медленного RPC. Клиентские RED-метрики — штатные grpc_client_*.

Обязательное правило мониторинга: finassist_outbox_oldest_age_seconds > 3600 для всех
target, включая пустой и unconfigured; пример выдержки 1 минута. Оно же покрывает
PurgeUserData: метрики библиотеки объединяют темы по получателю. Пороги и уведомления размещаются в infra
отдельно: наличие метрики не означает, что алерт уже включён.

Тесты: unit правил и адаптеров; реальные PostgreSQL-тесты истории, конкурентных
изменений/согласий, монотонности версии, отката события и гонки с tombstone; API-тесты
каждого из пяти RPC через полную сборку. Outbox проверяется с двумя настоящими gRPC
серверами: один заблокирован, другой получает новые события, возраст backlog виден,
после остановки и повторного запуска оставшиеся задания доходят без повторной доставки
уже подтверждённому получателю. Продовый сквозной стенд и соседние сервисы этим тестом
не подтверждаются.

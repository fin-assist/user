# Ошибки и повтор исходного RPC (FIN-225)

Контракт: `contracts/gen/go v0.5.0` (`471482b`), grpc-api.md 5.4–5.5. `user` не создаёт пользовательские тексты или severity: каталог принадлежит BFF. `common.v1.RequestRetryInfo` относится только к исходному RPC. Новая генерация помощника — отдельное свойство результата и в `user` не реализуется.

Usecase помечает ошибку через `domain.WithRequestRetry`. Обёртка сохраняет причину через Unwrap и не зависит от protobuf/gRPC. Адаптер `retryinfo.Apply` переносит только явное решение в уже корректный finerr. По имени причины, HTTP/gRPC-коду или типу неизвестной ошибки разрешение не выводится.

## Границы V1

- `true`: отказ первоначального лимитера Start до вызова провайдера; отказ IP-лимитера Register/Refresh/Watch после успешной фиксации его проверки, до проверки секрета/эффекта. RetryAt/RetryInfo сохраняют собственное ожидание. Это разрешение заново пройти проверки метода, а не обещание успешного результата.
- `false`: явная проверка неизменённых неверных данных, недействительного/истёкшего/использованного секрета, отсутствующего согласия или устаревшей версии документа; известные отказы constraint-маппера сохраняют ту же причину. Исправление входа или успешное восстановление авторизации образует предусмотренный контрактом исправленный контекст.
- Нет детали: неизвестная ошибка хранения/COMMIT, отмена/deadline, неопределённый результат Create/Recover провайдера, резерв/REQUEST_IN_PROGRESS, прежние cached результаты без advice. V1 не разрешает повтор по одному факту definite provider rejection или освобождения резерва.

Разрешение фиксируется в месте фактического отказа. Ответ callback преобразуется **до** кодирования idempotency-результата: auth handler делает это для Register/Refresh, небольшой StartEngine-адаптер — для телефонных исходов. При другой ошибке внешнего COMMIT прежнее решение callback не используется. При replay переносится только реально сохранённая деталь: старый cache не получает новое разрешение по коду.

`go-idempotency v0.4.1` на специальном cached phone RATE_LIMITED пересоздаёт ошибку из абсолютного RetryAt и теряет дополнительные детали; опубликованный v0.5.0 тоже не исправляет этот путь. Свежий busy/duplicate и его replay остаются без положительного advice. Отдельное исправление библиотеки требует мержа и нового опубликованного владельцем тега; локальный replace не применяется.

BFF соединяет service advice с доказанной безопасностью **всего REST-запроса**. `true` от сервиса не доказывает возраст UUID или окно ключа: keyed POST нового BFF остаётся false без такого доказательства. Ключ, тело, TTL регистрации/refresh, транзакции, бизнес-лимиты и протокол провайдера этим изменением не меняются. Чтения не получают синтетического true для неизвестной ошибки. Ошибка транспорта Watch после отправленного события остаётся завершением RPC с non-OK, не доменным terminal error.

## Проверки

Unit проверяет перенос true/false/отсутствия и исходной причины, сохранение retry metadata, неизвестный COMMIT и границы провайдера. Интеграционные проверки PostgreSQL проверяют сохранённый отказ и replay без эффекта. API вызывает полную сборку через сгенерированный клиент и проверяет реальную typed detail, лимит перед секретом/провайдером, false устаревшего согласия и отсутствие выдуманного advice у cached busy. Общие обязательные unit/integration/API coverage-gates остаются независимыми, с одним whole-module знаменателем.
